# 策略蜂巢（StratHive）产品规划

## 1. 产品定位

策略蜂巢是面向个人投资者的**策略化交易助理**。产品围绕策略组织交易想法、运行、资产分配、成交、对账和复盘，让用户从零散记账走向可跟踪、可复盘的策略化交易。

长期形态是 AI 辅助的交易工作台。系统记录事实、提示风险、辅助分析，用户负责判断、确认和执行实际交易。

- **目标用户**：个人投资者和希望把交易方法沉淀为可执行流程的策略实践者。
- **初始市场**：A 股沪深主板股票与 ETF，后续逐步扩展市场和品种。
- **产品形态**：个人本地应用，MVP 通过配套 Agent Skills 与用户交互，CLI 提供本机机器调用接口。下一期新增 Web UI。

## 2. 核心理念

1. **按运行复盘**。把成交、持仓和结果归属到一次具体的策略运行，并按该运行绑定的策略版本回看。
2. **账户真实，运行独立核算**。一个资产账户对应一个真实券商账户，可以承载多次运行。每次运行直接绑定一个资产账户，在启动和结束时完成资产分配和归还。
3. **先账本，后智能**。先把建账、资金、成交、交接和对账做成可信事实，再据此扩展分析、提醒和 AI 助理。
4. **用户主导**。用户决定策略如何运行、何时结束和怎样处置剩余资产，系统辅助记账和分析。
5. **逐步扩展**。通过真实策略验证运行模型，再从实践中沉淀模板、接口和分析能力。

## 3. 核心对象

| 对象 | 职责 |
| --- | --- |
| 策略 | 维护人工策略的名称和描述，并保留其不可变的版本记录。详细规则的结构和格式后续定义 |
| 策略运行 | 绑定所选策略的一个具体版本及一个资产账户，承载期初投入、当前资产、成交、状态和复盘 |
| 资产账户 | 对应一个真实券商账户，记录账户现金、持仓及佣金费率 |
| 交易日志 | 保存已成交事实及其运行归属，为持仓、费用和复盘提供依据 |
| 对账 | 核对券商状态、资产账户记录及运行归属汇总 |
| 复盘与分析 | 根据账本、策略上下文和行情估值计算绩效、归因和执行偏离 |

## 4. 顶层能力

### 4.1 策略运行与资产分配

用户创建运行时确定策略版本，启动时划入期初现金，也可以通过建账或交接承接已有持仓。期初本金由现金和已估值的承接持仓组成。运行期间现金与持仓随成交变化，首期的资金分配集中在运行边界。采用新版本时创建新运行，需要延续的持仓通过交接承接。

结束运行时，通过真实卖出或同账户持仓交接让其持仓归零，并将剩余现金归还账户。交接由新运行承接，历史成本继续用于账本核算，双方绩效采用同一交接估值。

### 4.2 账户、成交与对账

资产账户记录真实券商账户状态，成交按运行归属。对账同时核对券商状态与账户记录，以及账户总量与各运行汇总。持仓交接反映证券归属变化，交易日志保存真实成交。

### 4.3 复盘与辅助决策

复盘围绕运行起点、成交、资金占用和退出结果展开。先提供账本可直接计算的指标，再结合行情扩展市值仓位、收益、执行偏离、周期复盘和可解释提醒。

### 4.4 操作入口

用户通过 Agent Skills 完成账本操作。Skill 理解意图、确认关键输入并解释结果，CLI 把结构化请求交给 Core。未来 Web UI 复用 Core 的业务能力，TUI 根据终端使用需求另行评估。

## 5. 阶段演进

| 阶段 | 目标 |
| --- | --- |
| 0 · 策略运行账本 | 用户通过 Agent Skills 完成策略版本绑定、建账、固定期初分配、成交、对账、退出和持仓交接。CLI 契约通过自动化测试验证 |
| 1 · Web UI、分析与复盘 | 通过本机 HTTP 为同一 Core 提供 Web 界面，支持证券搜索、账本操作和分析展示，扩展仓位、盈亏、收益、偏离及周期复盘 |
| 2 · 新增 3～5 个策略 | 用不同真实策略验证运行、资产归属、交易记录、复盘与 Agent 操作的可复用性 |
| 3 · 回测与高级分析 | 扩展历史行情、独立模拟运行、组合与风险分析，逐步覆盖更多市场、品种和策略 |
