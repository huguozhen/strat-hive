# StratHive 数据源与 Linux 发布实施计划

## 1. 用户安装

首发验收平台为 **Ubuntu 24.04 x86-64**。GitHub Releases 提供 `strathive_<版本>_amd64.deb`、校验和及版本说明。安装包内置标准版 CPython 3.14、CLI、运行依赖、Skill 和 systemd 用户任务模板。

```sh
sudo apt install ./strathive_<版本>_amd64.deb
strathive setup
```

第二条命令以普通用户身份运行。向导先选择账本，再配置数据源、完成首次同步并启用每日刷新。Python 环境、SDK 依赖和命令路径由安装流程管理。向导完成后显示一段可复制给本机 Agent 的提示词，包含与安装版本一致的 GitHub Skill 目录和安装包内的备用路径。

## 2. 账本选择与数据存储

`strathive setup` 可以打开已有账本，也可以新建账本。打开已有文件时，先检查 SQLite 文件、StratHive 账本结构、版本及可写性，升级前生成一致性备份。新建时默认使用 `~/.local/share/strathive/ledger.sqlite3`，遵循 `XDG_DATA_HOME`，也可指定其他存储目录。目标文件已存在时引导用户打开已有文件。向导将选中的绝对路径保存到用户配置，供 CLI 和 Agent 使用。`--db` 可临时指定本次操作的账本。

| 数据 | 默认位置 | 恢复方式 |
| --- | --- | --- |
| 账本事实，包括资产账户、策略及版本、策略运行、资金分配、期初持仓、成交和交接 | 用户选定的 SQLite 文件 | 定期备份到另一块磁盘或其他存储介质 |
| 第三方证券目录及同步状态 | `~/.cache/strathive/reference/securities.sqlite3` | 按用户共享，清除后重新同步或导入，无需随账本备份 |
| 后续第三方行情及同步进度 | `~/.cache/strathive/market/` 下的独立数据库或数据文件 | 按标的和周期重新同步，无需随账本备份 |
| 账本路径、数据源选择及连接配置 | `~/.config/strathive/` 下的配置文件 | 重跑向导配置，凭据可重新录入 |

缓存和配置目录分别遵循 `XDG_CACHE_HOME` 和 `XDG_CONFIG_HOME`。新增数据先判断能否重建，以及是否影响历史业务结果。用户确认的费用、入账价格和交接估值保留在账本，可重新获取的原始数据和可重算的分析结果放到各自的缓存目录。后续若新增无法重建的用户数据，按用途决定是否归入账本，或单独持久化并指定备份方式。账本内保留解释历史成交和持仓所需的最少证券标识与快照，所有账本外键在账本内解析。目录刷新只更新目录库。

向导显示账本路径，说明其中的业务记录需要靠备份恢复，并建议定期备份到其他存储介质。使用 `strathive db backup --file /path/to/external-drive/strathive-backup.sqlite3` 生成一致性备份，避免运行期间直接复制 SQLite 主文件。备份包含账本所需的证券引用，恢复后可在离线状态查看历史交易和持仓。外部目录与行情可在联网后重新获取。

升级现有混合数据库时，先备份并验证旧账本，用旧目录初始化尚未建立的独立目录库。账本内的证券引用迁移和全量目录移除在同一次迁移事务内完成，提交前核对成交、持仓、资金和策略运行。迁移失败时保留原库可恢复，并允许重新执行。

## 3. 数据源配置向导

向导提供两个互斥选项。默认推荐 **银河星耀数智**，提示用户联系中国银河证券客户经理申请账号和密码。暂时无法提供账号的用户可选择 **公开证券目录**。以后可以重跑 `strathive setup` 切换。

### 银河星耀数智（推荐）

1. **安装 SDK**。向导通过 HTTPS 下载供应商 Gitee `v1.0.0` 的两个附件 `AmazingData-1.1.18-cp314-none-any.whl` 和 `tgw-1.0.9.2-py3-none-any.whl`。StratHive 每个发行版固定通过验收的附件 URL、文件名和 SHA-256。向导校验后将 SDK 安装到当前用户专用环境，再验证模块和原生库能否加载。 [银河 SDK 发布页](https://gitee.com/cgs2026/xysz/releases#release-v1.0.0) · [发布附件元数据](https://gitee.com/api/v5/repos/cgs2026/xysz/releases/tags/v1.0.0)
2. **处理安装异常**。自动下载地址失效、网络异常、校验失败或安装失败时，向导显示具体原因，指引用户从供应商发布页手动下载两个 wheel 并选择所在目录。向导继续负责识别、校验、安装和验证。用户也可重试或改选公开证券目录。
3. **配置并测试连接**。交互输入账号和密码，密码隐藏输入。先用默认地址 **`140.206.44.234:8600`** 测试，地址不可达时再提示填写 IP 和端口。认证失败时提示重新输入凭据。连接测试包括登录和一次实际证券读取，以区分连通性、认证和数据权限问题。
4. **首次同步并保存配置**。连接测试通过后，执行完整证券目录同步。成功后保存选定来源及连接配置。凭据仅写入权限为 `0600` 的用户配置文件，日志与命令结果使用脱敏信息。

### 公开证券目录

复用现有抓取逻辑。上海数据来自上交所，深圳优先使用深交所，深交所接口不可用时继续使用东方财富作为深圳目录的备用来源。选择后，向导直接执行首次同步并展示结果。 [公开目录适配器](../../src/strathive/sources/public.py)

首次同步失败时，向导提供重试、切换或退出。已有用户切换数据源时，在候选来源首次同步成功后才切换配置。定时任务始终刷新当前选定的来源，单次失败时继续使用上次成功的目录。

## 4. 证券同步与定时任务

- **银河适配器**。每次同步加载 SDK，登录一次，结束时退出会话。用 `BaseData.get_code_info` 分别拉取 `EXTRA_STOCK_A_SH_SZ` 和 `EXTRA_ETF`。用 `InfoData.get_stock_basic` 分批补齐股票全称、上市状态和板块，并按板块筛选沪深主板。ETF 使用目录简称，缺少全称时保留已有可靠值，否则留空。代码格式和板块枚举以脱敏实连样本确认。 [AmazingData 开发手册 §3.5.2](/home/claps/projects/yinhe-xysz/AmazingData开发手册.pdf)
- **公开目录适配器**。把现有脚本的请求和解析逻辑接入应用，输出同样的目录结构。仓库的 CSV 继续用于离线初始化，`security import` 用于手工导入。两种联网同步和 CSV 导入共用独立的目录数据库。
- **共用写入路径**。归一为 `SH.600000`、`SZ.159915` 等现有主键。完整取回股票与 ETF 后，校验范围、重复代码、品种和规模，在目录库的一次短事务内更新目录和最近成功记录。来源明确给出终止上市时才在目录中标记停用。主键相同但品种冲突时保留原值并报告。
- **命令**。`strathive security sync` 手动刷新。`security sync --if-stale` 供定时任务使用，当前来源在同一北京时间自然日已成功时跳过。`security sync-status` 返回来源、最近尝试和成功时间、更新条数及脱敏错误。手动和定时同步共用一个文件锁。网络阶段设总时限，对临时错误有限重试，SQLite 写事务仅用于提交。
- **每日调度**。两种来源共用用户级 systemd timer 和 `Type=oneshot` 服务，任务按用户刷新共享的目录库。首次配置成功后，向导启用定时器。每天**北京时间 09:15** 调用 `security sync --if-stale`，因为银河手册注明交易日目录在 09:00 前更新。`Persistent=true` 使用户定时器恢复时补跑一次。无 systemd 环境可以用 cron 调用同一命令。 [systemd.timer 手册](https://manpages.debian.org/bookworm/systemd/systemd.timer.5.en.html)

## 5. 构建、发布与升级

1. **固定运行环境**。项目 Python 约束设为 `>=3.14,<3.15`，提交 `.python-version` 并重生成 `uv.lock`。CI 和安装包使用同一验收通过的标准版 CPython 3.14 补丁版本。供应商手册的 Linux 推荐环境列的是 RHEL 7 系列，因此需在目标 Ubuntu 实测 TGW 原生库加载、依赖解析和 SQLite WAL 修复。 [AmazingData 开发手册 §3.2–3.5](/home/claps/projects/yinhe-xysz/AmazingData开发手册.pdf) · [uv Python 版本文档](https://docs.astral.sh/uv/concepts/python-versions/)
2. **构建安装包**。维护者用 `uv` 安装锁定依赖、运行测试、构建 StratHive wheel，再将 wheel、可在安装位置运行的 Python 运行时、锁定依赖、SDK 下载和安装工具、向导及配套文件组装为 Debian 包。系统安装部署程序和模板，`setup` 打开或新建用户选定的账本，并在用户目录写入配置、目录缓存、SDK 和用户任务。供应商 wheel 由向导从 Gitee 获取。 [uv 打包指南](https://docs.astral.sh/uv/guides/package/)
3. **发布版本**。版本号与标签 `vX.Y.Z` 一致。CI 使用脱敏样本，真实下载和银河接口验收在有权限的环境执行。干净 Ubuntu 环境验证通过后，将 Debian 包、`SHA256SUMS` 和版本说明上传到 GitHub Release 草稿，核对后发布。 [GitHub Releases 文档](https://docs.github.com/en/repositories/releasing-projects-on-github/managing-releases-in-a-repository)
4. **升级与回滚**。升级前暂停同步任务并备份账本。安装新版后，由向导迁移账本、检查 SDK 兼容性并恢复定时任务。回滚时安装上一版，并按需恢复对应的迁移前备份。

## 6. 实施顺序与验收

1. 验证 Gitee 附件下载、摘要、CPython 3.14 和 TGW 原生库。实连抽查沪深主板及沪深 ETF，确认接口权限、字段和品种覆盖。
2. 拆分账本与目录库，用包含历史成交、持仓和下市证券的旧账本演练迁移。仅用账本备份在空环境离线恢复，核对交易、资金与持仓，再重建目录并验证账本业务数据保持一致。
3. 接通两个来源的共用同步流程。覆盖首次同步、重复同步、离线查询、部分响应、重复代码、超时和鉴权失败。失败时核对目录及最近成功时间保持原值。
4. 验证向导能打开已有账本、在默认或自选目录新建，并提示备份。验证两个来源均能完成首次同步及每日刷新。模拟链接失效、手动提供 wheel、默认地址不可达、错误密码、来源切换和定时与手动并发。
5. 在未预装 Python 和 uv 的干净 Ubuntu 环境中，用安装包及 `strathive setup` 走通两条数据源路径。演练升级与回滚，检查日志、发布附件和版本库中没有账号密码。

## 7. 后续行情

银河是后续行情的首选来源。新增独立 `market sync` 命令和进度记录，复用 SDK 连接适配器。先用 `BaseData.get_calendar` 和 `MarketData.query_kline` 为持仓与关注标的补齐缺失交易日，按标的、周期和交易日去重，记录来源与估值口径。少量日线可在行情目录使用独立 SQLite 文件，批量历史和回测再考虑 Parquet。公开证券目录选项覆盖证券基础资料，行情按数据源能力单独配置。盘中持续订阅有明确需求后，再评估常驻进程。 [AmazingData 开发手册 §3.5.2.8、§3.5.4.2](/home/claps/projects/yinhe-xysz/AmazingData开发手册.pdf)
