# 策略蜂巢 (StratHive) — 产品规划

## 1. 产品定位

策略蜂巢是一款面向个人投资者的 **策略化交易助理产品**。产品以 **策略** 为组织核心，把交易想法、策略运行、资产分配、交易记录、对账和复盘放进同一套工作流，帮助用户从零散交易逐步走向可跟踪、可复盘、可演进的策略化交易。

产品长期形态是 **AI 辅助的交易工作台**：系统负责记录事实、组织策略、提示风险、生成复盘和辅助分析；用户始终负责判断、确认和最终交易决策。

- **目标用户**：个人投资者，以及需要把自有交易方法沉淀为可执行流程的策略实践者
- **初始市场**：A 股沪深主板股票、ETF；后续再扩展到其他市场和品种
- **产品形态**：Web UI + CLI + 后端服务，后续扩展到 agent / OpenClaw 调用
- **核心边界**：辅助记录、分析和决策，不直接替用户自动下单

---

## 2. 核心理念

1. **策略是产品主轴**
   系统不只是记录券商账户流水，而是把每笔交易、每段持仓和每次复盘归属到具体策略运行上，让用户知道交易行为来自什么策略、处于什么状态、产生了什么结果。

2. **账户真实，资产隔离**
   券商实际资产账户代表真实资金和持仓，逻辑资产池用于策略级资产隔离。系统需要同时尊重真实账户约束，又能让不同策略的资金、持仓和表现分开观察。

3. **先账本，后智能**
   AI 助理、提醒、复盘和策略生成都依赖可信交易事实。早期优先建设账户、逻辑资产池、交易日志和对账底座，确保数据准确，再基于这些事实扩展分析和智能能力。

4. **用户主导，系统辅助**
   产品可以提示、总结、解释和建议，但不越过用户做交易决策。任何策略执行、提醒响应和复盘结论都应保留用户确认、忽略、修正和备注的空间。

5. **渐进扩展，不过早抽象**
   先服务少量真实策略和真实交易流程，再从运行经验中抽象通用接口、策略模板和生态能力。平台能力应保持开放，但不在早期为假设场景过度设计。

## 3. 核心对象模型

- **Strategy（策略）**：交易方法、规则、信号来源或决策框架，可以是人工策略，也可以逐步扩展为半自动、代码或大模型辅助策略
- **Strategy Run（策略运行）**：策略在一段时间内的实际运行实例，用于承载资产、交易、状态和复盘
- **Broker Asset Account（实际资产账户）**：系统中对应真实券商账户的对象，用于承接真实资金、持仓和账户状态
- **Logical Asset Pool（逻辑资产池）**：从实际资产账户中划分出来的策略级资产空间，用于策略运行的资产隔离和核算
- **Trade Log（交易日志）**：记录交易事实的数据底座，是后续持仓计算、盈亏分析、复盘和 AI 总结的基础
- **Reconciliation（对账）**：校验系统记录与券商账户状态的一致性，保证后续分析建立在可信数据上
- **Review & Analysis（复盘与分析）**：基于交易日志、资产状态和策略上下文生成统计、归因、偏离记录和复盘结论
- **Assistant / Agent Interface（助理与代理接口）**：面向 CLI、后端能力和未来 agent 的调用层，用于查询状态、生成摘要、触发复盘和辅助决策

## 4. 顶层能力地图

### 4.1 策略与运行管理

管理策略定义、运行实例、运行状态和策略上下文，让用户可以围绕策略组织交易行为，而不是只围绕账户或标的查看交易。

### 4.2 资产账户与逻辑资产池

连接真实券商账户和策略级资产隔离模型，支持把一个真实账户中的资金和持仓映射到不同策略运行，形成后续核算和复盘的边界。

### 4.3 交易事实底座

沉淀完整、可校验、可归属的交易日志。交易日志是产品最重要的事实来源，支撑后续持仓计算、绩效分析、复盘和 AI 助理能力。

### 4.4 对账与数据可信

通过对账能力持续校验系统记录和真实券商账户状态，降低长期记账偏差，保证策略分析和复盘结论可信。

### 4.5 复盘与分析

基于交易日志和策略上下文生成持仓、盈亏、收益、偏离、执行质量等分析结果，并逐步形成日/周/月度复盘工作流。

### 4.6 提醒与辅助决策

在用户设定的策略框架内提供低频、可解释、可确认的提醒，例如策略条件触发、持仓关注、偏离提示和复盘待办。

### 4.7 开放接口与 Agent 协作

将核心查询、记录、分析和复盘能力封装为 CLI / API / agent 可调用能力，让 AI 助理可以围绕可信数据工作，同时保持用户在决策环路中。

## 5. 阶段演进

### 阶段 0：纯人工策略运行账本（MVP）

MVP 是一个支持纯人工策略的策略运行账本。该阶段验证核心对象模型是否成立：策略、策略运行、实际资产账户、逻辑资产池、交易日志和对账能否组成完整闭环。

阶段 0 完成后，系统实质上已经可以跑起来：用户能够创建人工策略，维护策略运行，记录真实交易，隔离策略资产，并通过对账确认系统记录可信。

### 阶段 1：基础数据分析、复盘与 Agent 接入

在可信交易数据之上，建设基础数据分析和复盘能力，包括持仓、盈亏、收益、执行偏离、交易理由对照和周期复盘等。

同时，将系统的主要操作能力封装为 OpenClaw skill / agent 可调用接口，包括策略管理、策略运行管理、账户与逻辑资产池维护、交易日志录入、对账、状态查询、数据分析和复盘。该阶段的目标是让用户可以通过 OpenClaw 等 agent 入口便捷使用系统，而不是每次都必须进入 Web UI 手动操作。

### 阶段 2：新增 3～5 个策略

在账本、分析和复盘闭环稳定后，新增 3～5 个真实可运行的策略，覆盖不同交易思路和使用场景。该阶段目标不是做策略市场，而是用多个真实策略验证平台对象模型、资产隔离、交易归属、复盘分析和 agent 接入是否具备可复用性。

### 阶段 3：回测与高级数据分析

在多个策略具备真实运行数据后，建设回测、高级数据分析和更完整的策略评估能力。该阶段关注策略历史表现、组合分析、风险暴露、参数对比、归因分析和更复杂的数据可视化，为后续更多市场、更多品种和策略生态扩展打基础。

## 6. 项目定位总结

- **品牌名**：策略蜂巢 (StratHive)
- **产品身份**：面向个人投资者的策略化交易助理
- **核心理念**：策略中心 + 可信账本 + 用户主导 + AI 辅助
- **长期目标**：帮助用户把交易经验沉淀为可执行、可复盘、可改进的策略系统
