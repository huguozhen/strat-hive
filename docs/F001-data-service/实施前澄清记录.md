# F001 实施前澄清记录

日期：2026-11-19。主要产品取舍已收敛，用户已同意最终简化方案；结论已同步到[主方案](数据服务实施方案.md)。本次仅修订文档，尚未启动代码实施。

## 第一轮结果

### Q1：首期估值时效——已明确

用户要求首期直接支持盘中估值，实时性不必特别高，但必须在盘中看到价格变化。

影响：原方案“首期仅用最近完整交易日收盘价、盘中行情延后到 P1b”的范围划分需要调整。收盘价不能再作为首期唯一行情能力。刷新方式及旧价降级见 Q6、Q8。

### Q2：期初及交接估值——由最终简化方案收敛

用户指出手工填写的应是持仓数量、成本价等事实，不应让用户手工填写估值。因此，第一轮当时没有确认“先交付只读估值，期初/交接估值改造后置”；最终范围按下文简化方案确定。

代码事实：现有 MVP 的期初持仓同时具有 `unit_cost` 与可空 `valuation_price`；交接可接收每证券 `price/source`。重放保留持仓成本，并用另一份价格计量运行期初投入和期末转出。缺少这份价格时可以交接，相关计量待确定。

概念及系统取价方向由 Q5 明确，计价和交互由最后一轮简化方案确定：首期以盘中估值为重心，期初/交接只增加自动取价、一次记账并回显的轻量补充，不单列复杂流程。

### Q3：银河依赖及降级——已明确原则

不把银河账号设为产品整体的强制前提。有必要依赖特定来源时，优先验证相应链路；无法提供时降级相关功能。

这不等于要求首发必须有无需账号的自动行情，也不等于已决定首发主数据源一定是银河。主来源按能力验证后排序，缺失行情时的展示原则见 Q7、Q8。

### Q4：实施门槛与数据源架构——已明确

用户要求先开发，不设置数据质量强制检查门槛。整体架构按数据源可插拔、可替换设计，后续能补充更多数据源。

影响：取消“阶段 0 全套通过、跨 3 个真实交易日观察完成后才能进入阶段 1”的开发依赖。不应把全部质量试验作为开工前置，也不能继续把 CNEquity 固定为盘中估值的必经路径。数据源能力及失败原因仍需如实返回，不以模拟数据冒充真实行情。

## 第二轮结果

### Q5：成本与运行边界市值——已明确原则及新增约束

用户同意保留成本与边界市值的不同计量：用户记录数量、成本、时间等事实，系统取得价格并计算估值；取不到价格时可以记录事实，相关市值待确定。

用户增加要求：期初/交接必须在盘前或盘后进行；用户记录后，系统须计算并回显估值供核对，保障期初计量起点准确。

这些约束最终通过下文简化方案落定，不再增加专门的预览/提交或人工估值操作。普通盘中查询的旧价降级不能冒充对应时点的正式边界计量。

### Q6：盘中刷新方式——已明确

首期主动查询时获取快照，允许短暂缓存，目标约 1–5 分钟的变化粒度。不要求后台持续推送或盘中曲线；真实延迟按来源能力显示。

### Q7：首条链路与来源优先级——已明确

先围绕盘中快照接通来源，必要时优先验证银河等实际依赖链路。不同类型数据按实际验证结果选择来源优先级，可以来自不同来源。

CNEquity 历史能力独立推进，不作为首期盘中估值的必经前置。这里的验证是确认具体链路能否使用，不恢复 Q4 已取消的整套质量开工门槛。

### Q8：查询降级——已明确

盘中来源失败时，可以展示明确标记了价格时间和失败原因的缓存价；无盘中缓存时可展示上一交易日收盘价估值。完全缺价的持仓保留数量及缺价项，相关完整总资产保持未确定，不以成本或零价代替。

## 最后一轮：撤回复杂拆分，采用统一简化方案

曾提出 Q9–Q12 继续细分时点、价格、确认步骤和交付范围。用户认为这使期初/交接过于复杂，要求重新思考；这四个问题没有逐项获准，不能作为用户确认记录。

随后提出以下统一简化方案，用户明确回复“同意”：

1. 用户记录现金、数量、成本和生效时间等事实，期初/交接在盘前或盘后进行。
2. 系统自动取价：盘前使用上一交易日收盘价，盘后使用当日收盘价，计算市值并保留价格日期及来源。
3. 一次记账完成并回显事实、成本和市值供核对；不增加用户填写估值、独立预览文件或二次确认。
4. 缺价不阻塞事实入账，显示待估值，后续可以由系统补齐；市值只用于运行计量，不改变持仓成本。
5. 首期重心仍为盘中按需估值；期初/交接仅做上述轻量补充，不扩展为完整绩效管理。

## 对原方案的主要调整

- 盘中行情进入 P0，删除“首期只支持收盘估值、盘中留到 P1b”的安排。
- 数据源按能力可替换和分别排序，银河可选，CNEquity 历史能力独立推进。
- 删除阶段 0 整套质量门槛及跨真实交易日观察的开发前置；必要依赖在实施中优先试通。
- 删除冻结候选估值文件、独立交接预览/提交及二次确认流程。
- 保留最少的价格时间/来源、待估值及补齐能力，支持业务解释，不建设独立估值证据管理子系统。

剩余的供应商权限、字段、运行环境和实际时延属于可验证的实施事实，按已确认的可替换、可降级原则处理，不再作为需要用户预先拍板的产品问题。
