# 历史可选组件与 Skill 集成

实施日期：2026-11-24。基于已合并的 F001 PR #8，分支 `feature/optional-history-component`。本轮把历史数据作为可随时安装／卸载的软件组件交付，继续使用原历史库格式，不增加账本迁移。

## 用户入口

- `setup` 在账本和数据源配置之后提供可选历史组件安装，默认跳过；退出数据源配置也能选择组件，不把它绑定到银河账号。
- `data history install` 下载并校验与主包匹配的独立制品，复用当前 Python 3.14 创建独立环境。`--repair` 检查并重建损坏或需要切换运行时的环境，检查通过才保存配置，原环境保留。
- `data history uninstall` 停止并移除历史用户任务，删除组件管理的环境和下载缓存，移除历史收盘／日历路由；保留行情、修订、同步进度、分钟清单、配置及投资账本。用户自备环境、主包 Python 和共享 DuckDB 扩展缓存保留。
- 安装与同步分开：安装不采真实行情、不自动启用定时器。重装连接原数据目录，按 `data sync` 请求补齐行情。
- 安装进度进入 stderr，业务结果仍是 JSON。下载最多重试三次，完整缓存校验后复用；失败清理本次候选环境，保持原配置。安装软件目录需要至少 2GiB 临时空间；历史库继续采用原 20GB 预警／10GB 暂停写入阈值。

## 分发与运行环境

主包含 Python、轻量 CLI、安装管理代码和发布制品清单；CNEquity、Polars、Arrow、pandas、NumPy 等作为单独的 wheel 压缩制品分发。源码或尚未生成清单的构建返回 `history_artifact_unavailable`，不静默改为安装最新版或要求用户准备 Git。

`build.py` 在构建环境使用固定 CNEquity commit 和带哈希的依赖锁构建 wheel。只有源码发行的依赖在构建阶段转换为 wheel，然后在一个没有构建工具的干净虚拟环境中安装并运行 `pip check`，确认依赖闭包完整。发现并补回了原锁文件顶部遗漏的 `annotated-doc` 项，产物现有 41 个 wheel。

发布构建生成 `history-component.json`，包含源提交、Python／平台、制品地址及 SHA-256。`.deb` 嵌入这份清单，Release 另外提供压缩制品和清单，校验和覆盖主包、组件和清单。客户端仅安装带哈希的 wheel，不使用 uv、Git、编译器或源码构建；同版本离线制品可通过 `--bundle` 使用，扩展首次准备仍需要网络或已有缓存。发布前不会把本地制品推送为正式 Release。

历史进程通过组件自己的 Python `-I` 启动，入口只加载 StratHive 的 worker 包，不把 Core 整个 site-packages 加入 PYTHONPATH。实际检查历史进程使用 click 8.4.2，Core 使用 click 8.5.1，确认同名依赖没有相互覆盖。软件读写的生命周期锁与历史库单写者锁配合，环境被使用时拒绝移除。

新增 release 检查：主机安装组件以准备扩展缓存，随后在无网络、没有系统 Python／uv／Git 的 Ubuntu 容器中，从独立制品和扩展缓存安装／检查／卸载，检查历史库保留且账本可备份。当前宿主机没有 Docker；该容器步骤已加入工作流，仍待 release CI 实际执行。

## Skill

统一更名为 `strathive`，主入口按任务读取三个流程：

- 账本：账户、策略版本、运行、成交、交接、对账和估值，保留原记账约定。
- 行情：快照、历史 K 线、复权／聚合／导出、显式同步范围与缺口含义。
- 组件：安装／修复／卸载、故障重试、离线制品与数据保留。

`setup` 提示、README、安装包内 Skill 路径及 release 检查均改为新名称。已安装的旧 `strathive-ledger` 仍可调用兼容的账本 CLI；需要新能力时安装新 Skill，而不再增加一个含义重叠的数据 Skill。

- 容器执行、正式制品发布和全市场价格回填未在本轮启动。
