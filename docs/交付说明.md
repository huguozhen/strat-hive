# 策略蜂巢 3.1–3.3 交付说明

## 交付范围

本次交付覆盖《MVP产品功能》3.1 策略管理、3.2 策略运行管理、3.3 资产账户与逻辑资产池，提供本机 Web 操作界面及 JSON HTTP 接口。

- **策略**：创建、列表、详情、修改名称与描述；可关联多个运行实例。
- **策略运行**：创建并绑定一个未被绑定的资产池，查询资产及持仓；支持待启动 → 运行中、运行中 → 已暂停、已暂停 → 运行中，以及待启动/运行中/已暂停 → 已结束。结束后不能恢复；一个池只能绑定一个运行实例。
- **账户**：创建、维护账户名称、现金、持仓及佣金费率；现金账户无需策略即可创建。已有持仓或维护时新增持仓，必须填写承接策略、资产池和运行名称，系统在同一事务创建并分配持仓。支持同时为承接池分配现金。
- **资产池**：创建池、初始分配现金、现金划入和划出、查看现金与持仓成本；账户详情展示账户与池汇总、未分配现金和证券数量、成本一致性。账户现金包含池现金，划转仅改变归属，不改变账户总现金。
- **展示**：仅展示现金、数量、成本等确定性信息。当前没有订单，现金占用固定为 0；没有行情、市值、浮盈和收益率。

交易日志（3.5）、券商账户即时对账（3.4）、完整 CLI（3.7）不属于本次实现范围。运行详情中的交易日志区域明确标记为未实现，不能记交易，当前账户状态只能人工维护，不能视为完整交易记账闭环。

## 启动与停止

需要 Python 3.10 或更高版本；仅使用 Python 标准库及浏览器，不需要安装第三方依赖。当前环境验证版本为 Python 3.15.2。

```bash
cd /home/claps/projects/strat-hive
python3 server.py
```

服务默认监听 `0.0.0.0:8000`。本机访问 `http://127.0.0.1:8000`，其他设备访问 `http://开发机IP:8000`，并确保防火墙及网络允许连接。在启动终端按 `Ctrl+C` 停止。更换端口或数据库路径：

```bash
python3 server.py --port 8080 --db /绝对路径/strathive.db
```

也可通过 `STRATHIVE_DB` 环境变量设置默认数据库路径，`--db` 优先。默认数据文件为项目目录下 `data/strathive.db`，首次启动自动创建。服务没有账号鉴权和 HTTPS，能够连接端口的用户都可以读取和修改账本；仅应在可信开发网络中使用，通过防火墙或 VPN 限制访问。若只需本机访问，可指定 `--host 127.0.0.1`。通过域名访问时需显式添加 `--allowed-host 域名`，该参数可重复指定；IP 地址和 localhost 默认允许。

## 使用流程

1. 在「资产账户」创建账户，输入现金和佣金费率。费率按小数填写，例如万分之三为 `0.0003`。如有持仓，逐条录入证券代码、名称、数量、每股/份成本价及持仓日期，并填写承接策略、池、运行和分配现金。
2. 对纯现金账户，在「策略管理」创建策略，在「逻辑资产池」选择账户并分配现金，再在「策略运行」将策略与未绑定的池关联。
3. 在运行卡片启动、暂停或结束；查看详情可以看到绑定池、现金和持仓。
4. 在资产池执行现金划入或划出；账户详情展示总量与未分配部分。账户现金不能低于池内现金总和，池也不能划出超过其可用余额的现金。
5. 维护账户时，完全分配给单个池的既有持仓修改或删除会原子同步到该池。对于被部分分配或被多个池共同持有的历史数据，为避免擅自决定分配比例，系统拒绝自动同步，需后续增加明确的持仓分配调整功能。新增持仓须创建新的承接组合。

现金金额精确到分，持仓成本价最多四位小数，佣金费率最多六位小数；数量为正整数。系统只做沪深主板股票及沪深 ETF 常见六位代码段格式校验，**没有证券主数据或券商接口，不能验证代码是否真实存在、名称是否准确或证券是否已退市**，录入前需自行核实。持仓日期按用户输入记录，不进行行情或交易日校验。

## 数据、备份与边界

采用 SQLite，账户、持仓、池、策略与运行使用外键和唯一约束；关键写操作采用 `BEGIN IMMEDIATE` 事务，避免并发超额分配和部分承接。只维护当前状态，不生成历史快照。资产池的「分配现金」在本阶段表示累计净划入，等于当前可用现金；未来交易模块应根据交易事实维护现金、占用和成本。

备份时先停止服务，再复制 `data/strathive.db` 到安全位置；恢复时先停止服务并替换数据库文件。数据库是未加密的本地文件，包含账户信息，应自行保护操作系统用户及备份文件的访问权限。数据库结构尚无版本迁移工具，后续升级前应先备份。

## 项目结构与接口

- `server.py`：本机 HTTP 服务和 JSON 接口。
- `strathive/core.py`：SQLite 数据模型、校验及事务业务逻辑。
- `static/`：Web 页面、样式和交互脚本。
- `tests/test_ledger.py`：核心业务自动化测试。
- `docs/`：原始需求与本交付说明。

`GET /api/state` 返回账户、策略、资产池和运行的当前状态；`POST /api/strategies`、`/api/accounts`、`/api/pools`、`/api/runs` 创建相应对象；`POST /api/strategies/{id}/update`、`/api/accounts/{id}/update`、`/api/pools/{id}/transfer`、`/api/runs/{id}/status` 执行更新、划转和状态变更。接口接收 JSON，错误返回 `{"error":"..."}`。接口定位为开发预览使用，未经版本化，不提供鉴权或兼容性承诺。

## 验证

```bash
python3 -m unittest discover -s tests -v
node --check static/app.js  # 可选，需 Node.js
```

自动化测试覆盖纯现金建账、持仓承接及失败回滚、现金划转与超额限制、并发资产池分配、账户持仓同步、唯一绑定、状态转换及输入校验。实际 HTTP 冒烟检查覆盖页面与脚本请求、承接建账、状态变更、超额划转拒绝和跨来源请求拒绝。

另以临时 DOM 测试环境验证了包含持仓的 Web 建账表单和运行详情。当前机器未安装图形浏览器，因此未进行真实浏览器的视觉验收。
