# 策略蜂巢 (StratHive) — MVP 版本产品功能设计

## 1. MVP 定位

MVP 目标：**策略运行账本**  
- 验证核心对象模型是否成立：策略 → 策略运行 → 逻辑资产池 → 交易日志/对账  
- 首期仅支持 **A股沪深主板股票、ETF**；实现架构适当预留后续市场和品种扩展能力
- 支持人工策略，手动维护交易日志  
- 支持实际资产账户与逻辑资产池，一个策略运行实例绑定一个逻辑资产池
- 支持首次建账时录入当前现金和已有持仓；账户已有持仓时，强制引导创建承接用的策略、逻辑资产池和策略运行实例
- 创建实际资产账户时填写券商佣金费率，用于交易日志中手续费（券商佣金）的自动计算
- MVP阶段只维护系统内最新账户状态，不做多版本账户快照
- MVP阶段只展示现金、持仓数量、持仓成本、费用明细等确定性指标，不展示资产总值、持仓市值、浮动盈亏、收益率等依赖实时行情的指标
- 支持用户输入或导入券商最新账户状态并即时对账，校验券商账户信息与系统内账户信息一致性
- 自行开发交易日志模块，作为记账的数据底座
- MVP 聚焦资产账户、逻辑资产池、交易日志和即时对账闭环，先把记账做完整、做准确

---

## 2. 核心对象

- **Strategy（策略）**：人工策略，保留长期可扩展对象
- **Strategy Run（策略运行）**：策略实例，绑定一个逻辑资产池
- **Broker Asset Account（实际资产账户）**：系统内记录的券商资产账户，用于维护真实账户在系统内的最新现金、持仓状态和券商佣金费率
- **Logical Asset Pool（逻辑资产池）**：从实际资产账户中划分出来的策略级资产池，用于策略运行的资产隔离和核算
- **Trade Log（交易日志）**：自研模块，包含交易流水、标的、成交价格、成交数量、手续费（券商佣金）、印花税、过户费、理由、备注和策略运行归属
- **Reconciliation（对账）**：用户输入或导入券商最新账户状态后，系统即时校验券商账户信息与系统内实际资产账户、逻辑资产池汇总、现金和持仓的一致性。MVP阶段不持久化对账记录

## 3. MVP 功能

### 3.1 策略管理
- 创建人工策略
- 查看策略列表
- 查看策略详情
- 编辑名称与描述
- 不支持复杂策略或自动策略开发

### 3.2 策略运行管理
- 基于策略创建运行实例
- 设置运行名称
- 绑定一个逻辑资产池
- 查看逻辑资产池分配现金、可用现金、持仓数量、持仓成本和现金占用
- 启动 / 暂停 / 结束策略运行
- 查看策略运行详情（逻辑资产池、交易日志、当前资产状态）
- 策略运行详情只展示确定性指标，例如现金、持仓数量、持仓成本、交易费用明细和已记录交易流水；不展示依赖实时行情的浮动指标

### 3.3 资产账户与逻辑资产池
- 创建和维护实际资产账户
- 创建实际资产账户时填写券商佣金费率
- 首次创建实际资产账户时录入当前现金、已有持仓、成本价和持仓日期
- 如果账户已有存量持仓，强制引导创建承接用的策略、逻辑资产池和策略运行实例
- 如果账户只有现金、没有持仓，只创建实际资产账户，后续由用户按需创建逻辑资产池和策略运行
- 支持以“存量承接”方式初始化逻辑资产池和策略运行，作为后续记账和对账的起点
- 维护实际资产账户的最新现金、最新持仓、成本信息和券商佣金费率
- 不维护账户历史快照，也不做多版本状态管理
- 基于实际资产账户创建逻辑资产池
- 一个策略运行实例绑定一个逻辑资产池
- 支持逻辑资产池的初始资产分配、现金划入、现金划出、现金余额、持仓数量和持仓成本查看
- 支持汇总逻辑资产池，和实际资产账户进行总量校验
- 资产账户和逻辑资产池页面只展示确定性指标，不展示资产总值、持仓市值、浮动盈亏、收益率等依赖实时行情的指标

### 3.4 账户对账
- 手动录入或导入券商最新账户状态，包括现金、持仓数量、成本等字段
- 对比系统内实际资产账户与券商最新账户状态
- 对比逻辑资产池汇总结果与系统内实际资产账户信息
- 展示现金、持仓数量、持仓成本、逻辑资产池汇总等不一致项
- MVP阶段不保存对账记录、不维护对账历史、不要求用户填写差异处理备注
- 如果是盘中对账，跳过依赖实时价格的指标对比，例如市值、浮动盈亏、收益率等；只对现金、证券代码、持仓数量、成本等相对稳定字段做比较

### 3.5 交易日志模块
- 自行开发交易日志数据模型和录入流程
- 支持交易日志明细的新增、查看、编辑和删除
- 支持手动记录买入/卖出
- 支持将已有持仓作为建账初始化记录，不强制要求补录完整历史交易
- Web UI 录入交易时，标的选择支持按证券代码或名称搜索、选择，并做有效性校验
- CLI 录入交易时，标的支持输入证券代码或准确证券全称，并做有效性校验；不支持模糊名称匹配
- 交易录入只支持按交易数量录入，不支持按金额录入
- 成交金额由成交价格和成交数量计算，不作为独立录入方式
- 交易日志明细包含标的代码/名称、交易方向、时间、成交价格、成交数量、手续费（券商佣金）、印花税、过户费、理由、备注
- 手续费（券商佣金）按实际资产账户的券商佣金费率自动计算
- 印花税、过户费按 A股股票/ETF、买卖方向、成交金额和成交数量等规则自动计算
- MVP阶段交易费用规则写死，不提供用户配置入口
- 自动计算出的手续费（券商佣金）、印花税和过户费均允许用户手动覆盖，以匹配券商实际成交回单
- 交易成本合计作为展示字段，由手续费（券商佣金）、印花税和过户费汇总得出
- 交易日志明细归属于策略运行
- 支持按策略运行、标的、时间范围筛选交易
- 支持基础字段校验和交易数据完整性校验
- 历史交易补录、批量导入和复杂归因放到后续增强；MVP 优先保证手动录入闭环

### 3.6 Web UI
- 创建策略、策略运行
- 创建实际资产账户，录入当前现金和已有持仓
- 创建实际资产账户时录入券商佣金费率
- 账户已有持仓时，引导创建承接用策略、逻辑资产池和策略运行
- 绑定逻辑资产池，启动策略运行
- 录入和管理交易日志，支持标的代码/名称搜索选择、按数量录入、费用明细自动计算和手动覆盖
- 录入或导入券商最新账户状态并执行即时对账
- 查看策略运行详情、逻辑资产池、交易日志和当前资产状态
- 仅展示确定性指标，不展示资产总值、持仓市值、浮动盈亏、收益率等依赖实时行情的指标

### 3.7 CLI
- 创建策略、策略运行
- 维护实际资产账户和逻辑资产池
- 录入当前现金、已有持仓和券商佣金费率
- 维护交易日志，支持输入证券代码或准确证券全称、按数量录入、费用明细自动计算和手动覆盖
- 查询策略运行摘要、逻辑资产池、交易日志和当前资产状态
- 执行对账并查看差异
- 可为未来 agent / OpenClaw skill 调用预留接口

## 4. MVP 明确不做
- 自动交易  
- 券商接口自动接入  
- 网页可配置策略规则  
- 策略模板市场  
- 自动选股  
- 回测系统  
- 新闻事件理解  
- 大模型策略生成  
- 多市场、多品种完整支持  
- 复杂数据分析组件集成  
- 持仓、盈亏、复盘数据计算与分析  
- 实时行情接入和依赖实时价格的指标展示  
- 多版本账户快照和账户历史快照管理  
- 对账记录持久化、对账历史和差异处理工作流  
- 历史交易批量导入和复杂补录工具  

---

## 5. MVP 成功标准
- 用户能将真实交易日志维护到策略运行下  
- 实际资产账户和逻辑资产池能表达真实券商账户与策略资产分配关系  
- 已有持仓的券商账户能通过建账初始化和存量承接进入系统，并进入后续记账流程  
- 只有现金、没有持仓的券商账户能先作为实际资产账户存在，不强制创建策略运行  
- 一个策略运行实例能稳定绑定一个逻辑资产池  
- 逻辑资产池实现策略级资产隔离  
- 即时对账能发现券商最新账户状态与系统内账户信息的差异  
- 盘中对账能跳过依赖实时价格的指标，只核对现金、证券代码、持仓数量、成本等稳定字段  
- 自研交易日志模块能支撑交易明细的完整管理  
- 交易日志能按数量录入，并能校验标的代码或准确名称  
- 系统能基于券商佣金费率和 A股规则自动计算手续费（券商佣金）、印花税、过户费，并允许用户覆盖  
- MVP页面和CLI摘要只展示确定性指标，不展示依赖实时行情的浮动指标  
- 资产账户、逻辑资产池、交易日志和即时对账结果能形成完整记账闭环  
- CLI / Web UI 流程顺畅，未来可扩展 agent 调用
